# Egress Audit — "no data leaves your deployment"

**Claim under audit:** the product's **runtime** makes outbound HTTP calls only to
(i) the **customer's own LLM endpoint** (BYO-LLM, decision D1) and (ii) the
**customer's own target site** being scraped (which is itself SSRF-guarded).
No telemetry, no update checks, no PyPI/uv calls, no third-party beacons.

**Verified:** 2026-08-17 · **Gate:** `python scripts/audit_egress.py` — wired into
`scripts/smoke.py` (Gate 0) and CI; **fails** if an unrecognised outbound call
site is added to the product runtime.

## 1. Scope

| In scope (product runtime) | Out of scope (deliberate) |
|----------------------------|---------------------------|
| `src/` — every module shipped in the product image / CLI / UI | `scripts/ci_*`, `scripts/debug*`, `scripts/eval/*` — **dev/CI tooling**: they call GitHub/GitLab APIs during development and self-test only |
| `generated_tests/conftest.py` — the evidence/learning teardown shipped with every generated package | The customer's CI Action outbound traffic (customer's LLM + their own platform APIs — documented in `FEATURE_SPEC_phase7_ci_cd_integration.md` §9) |
| `streamlit_app.py`, `cli/main.py` — product entrypoints | |

## 2. What counts as outbound HTTP

Scanned primitives: `httpx.{get,post,put,patch,delete,head,stream,Client,AsyncClient}`,
`requests.{…}`, `urllib.request.{urlopen,Request,build_opener}`, `urllib3`,
`aiohttp`. Excluded as **not** traffic: `urllib.parse` (pure URL manipulation),
type/exception names (`httpx.ConnectError`), identifiers ending in `requests`
(`pass3_requests`), and Playwright navigation (that is the *target* traffic,
guarded separately by `src/url_guard.py`).

Classification: a call site is **USER-CONFIGURED** when its statement references a
user-configurable or target-derived address (any `*_url` identifier, `endpoint`,
`base_url`, `candidate`, `probe_url`, env reads, `localhost` literals). Anything
else is **FLAGGED** and fails the gate.

## 4. The other half: inbound (what the scraper may *reach*)

The no-egress claim has two halves. Outbound (this doc) is verified by the gate.
**Inbound reachability** of the scraper — the SSRF guard — is the companion
feature: `src/url_guard.py` refuses scraping of link-local/metadata addresses
(including `169.254.169.254`), private networks (opt-in), and non-http(s)
schemes at every navigation entry point, plus a request-level handler for
redirects and sub-resources. See `FEATURE_SPEC_phase6_saas.md` §5.1 and
`tests/test_url_guard.py`.

## 5. Running the gate

```bash
python scripts/audit_egress.py          # human table + verdict; exit 0/1
python scripts/audit_egress.py --json   # machine-readable manifest
python scripts/smoke.py                 # Gate 0 includes the egress audit
```

**Policy:** any new outbound-HTTP call site in the product runtime must either
target a user-configured endpoint or be deliberately allow-listed *in this
document with a reason*. The gate fails otherwise — a "quick telemetry call"
cannot land silently.
