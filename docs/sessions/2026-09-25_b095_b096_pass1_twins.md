## 1. B-095 — a worktree run silently tested MAIN's `src`

`scripts/eval/eval_harness.py` and `eval_resolver.py` defined `_PROJECT_ROOT` but never
`sys.path.insert`ed it. Run as a script, `sys.path[0]` is `scripts/eval`, so every deferred
`from src... import` resolved through the site-packages editable install back to the **main
checkout**. A worktree fix was invisible to the harness unless `PYTHONPATH` was exported.

Fix: insert the checkout root at `sys.path[0]` in both entry points. `eval_runner`/`eval_metrics`
are script-local and are not shadowed (nothing of those names exists at the project root).

Proof: `tests/test_b095_eval_checkout_path.py` builds a throwaway checkout with a sentinel `src/`
and a decoy `src/` on `PYTHONPATH`, runs the real entry-point bodies, and checks which `src/` won.
The control leg strips the guard and asserts the decoy wins — the test has teeth. Live probe from
the worktree now reports `src.placeholder_orchestrator.__file__` under the worktree.

## 2. B-096 — Pass-1 first-match and same-page twins

The Session 11 residual was three descriptions: `driving license number` and `years licensed`
picked the `addDriver*` twin over the account-holder `main*` field, and `vehicle registration
number` was won by `#vehicleMake` in Pass 1.

### Root causes (found this session, not the ones the backlog guessed)

1. **Required-field marker asymmetry.** The real fields carry the marker
   (`text="Years Licensed *"`), the optional twins do not (`"Years Licensed"`). Pass 1's
   `norm_text in norm_description` rule matched the optional twin exactly and never saw the
   required field, so it returned the only textual hit.
2. **Garbage `accessible_name`.** On the live pipeline pool the scraper records
   `accessible_name="*"` for `#mainLicenseYears` / `#mainLicenseNumber` (the required `<span>*</span>`
   leaks into the accessible-name computation). `normalise_element_text` trusted
   `accessible_name` over `text`, so the real label was hidden — the required field was not even
   a Pass 1 candidate.
3. **Pass 1 returned the first match without consulting the scorer.** Several equal-rule matches
   were resolved by scrape order, not intent.
4. **`license` ⊆ `licensed`.** The single-word key-phrase rule used a raw substring check, so
   `license` matched `Years Licensed`; the word-ratio guard (strict `< 3`) also blocked the
   legitimate `license` → `Driving License Number` match (ratio exactly 3).

### Fixes

| Where | Change |
|---|---|
| `src/role_mapper.py` `normalise_element_text` | Strip required markers (`*`); collapse whitespace; if a source normalises to nothing (e.g. `accessible_name="*"`), fall through to the next source instead of shadowing the real text. |
| `src/element_matcher.py` `pass1_text_match` | Collect every exact-text and every equal-rule match, then tie-break with `_pick_best_text_match` (the deterministic `rank_candidates` ranking) instead of returning the first in scrape order. |
| `src/element_matcher.py` single-word phrase rule | Require a word boundary (`\bphrase\b`); allow word-ratio `== 3` for single-word phrases (a one-word label against a three-word field label is a strong signal). Applied to both the FILL/CLICK and ASSERT paths. |

`_pick_best_text_match` returns a single candidate unchanged, and falls back to the first
candidate when the scorer drops all of them, so behaviour degrades to the pre-B-096 result rather
than to no match.

in-process repro of the live failure without the LLM.

## 3. B-094 — two stories on one site overwrote each other's test file

`_persist_regenerated_tests` named the emitted file from the **site**
(`test_<site>.py`), so `eval-007` and `eval-008` (both `banking_mock`) wrote the same
`test_banking_mock.py`. `_load_test_files` then matched by `site in stem`, so both stories
resolved to that one file: eval-007's 8 tests never ran and were reported as eval-008's.

Fix, naming only — **no DB schema change** (the `eval_runs` table already keys on `story_id`):

- new `_story_test_filename(story_id)` → `test_<slug(story_id)>.py` (e.g. `test_eval_007.py`)
- `_persist_regenerated_tests` writes per story; `_load_test_files` matches the exact per-story file

Historical `eval_runs` rows for eval-007/008 are unrecoverable (the file was overwritten); the
`created_at` + `git_commit` columns separate them from post-fix rows. Test:
`scripts/eval/eval_runner_test.py::TestSameSiteStoriesDoNotCollide`.

Verified end-to-end by the full held-out run: `scratch/gate1_out3/` holds 9 distinct
`test_eval_0NN.py` files, `test_eval_007.py` ≠ `test_eval_008.py`, and the two banking stories
report their own numbers (7/13 and 10/13 placeholders; 8 and 9 tests).
