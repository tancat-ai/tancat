### Problem
Placeholder resolution is 38% of pipeline time (~42s per site). The main bottleck is the **journey resolution loop** in `PlaceholderOrchestrator` — each placeholder in a test journey calls `_resolve_placeholder_for_page()` → `ElementMatcher.find_best_element_for_current_page()` → Pass 3 LLM call (one per placeholder with multiple candidates).

### What's Done
Batching is implemented for the **fallback loop** (the "resolve remaining placeholders" pass at line ~404 of `placeholder_orchestrator.py`). This handles placeholders that weren't resolved during journey context. The infrastructure is in place:

- `SemanticCandidateRanker.choose_best_candidates_batch()` (`src/semantic_candidate_ranker.py`) — takes `items: list[dict]` each with `action`, `description`, `candidates`, returns per-item results in one LLM call
- `ElementMatcher.find_best_elements_batch()` (`src/element_matcher.py`) — takes `requests: list[dict]`, runs Pass 0-2 per request, collects Pass 3 candidates, calls `choose_best_candidates_batch()` once
- Fallback loop (`src/placeholder_orchestrator.py`) already uses `find_best_elements_batch()` for unresolved placeholders
