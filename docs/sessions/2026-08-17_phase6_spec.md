Key design decisions made in the spec (all flagged for grilling in §9 where they're proposals):

1. **SSRF guard (`src/url_guard.py`)** — three-layer: scheme restriction (http/https); ALWAYS-block link-local (incl. `169.254.169.254` metadata), unspecified/broadcast, multicast, IPv4-mapped IPv6; loopback default-ON for local/UI use (the mock-site family depends on it; it never leaves the deployment) but blocked in CI/team contexts; private ranges (10/8, 172.16/12, 192.168/16, fc00::/7) blocked by default with `allow_private_networks: true` opt-in for internal staging. Resolve-and-check with first-hop IP pinning + a `page.on("request")` redirect hook; documented limitation (sandboxed egress proxy = Part 2). Composes *under* the Phase 7 danger-zone check — `--danger-zone` can never unblock link-local.
2. **Egress audit** — `scripts/audit_egress.py` static scan of product runtime (`src/` + generated-package runtime + entrypoints), asserts every outbound call site is user-configured or allow-listed; CI Gate 0; renders `docs/security/egress-audit.md` as the public verification note.
3. **License = entitlement marker, not DRM** (consistent with Phase 7 spec §13): offline ed25519-signed token, 7-day grace, unlicensed = free tier (never a lockout of the OSS core). Explicit honesty note in spec + ToS.
4. **Free tier = runs/credits**: meter reads existing `run_results.sqlite`; "run" = one pytest execution of a generated package; N runs + M exports per 30 days; generate stays free.
5. **Credential policy verification-first**: CI secret audit (GH + GL), screenshot-redaction *test* (redaction pass only if it fails), ToS clause drafted, D4 rule ("never learn which login unlocks which element") gets verification tests.
6. **Team concurrency = cheap v1**: one server/process + cross-process file lock + AI-029 workspace isolation; no DB swap (ChromaDB/hosted Milvus documented as the escape hatch).
