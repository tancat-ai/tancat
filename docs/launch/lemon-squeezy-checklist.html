TanCat launch — Lemon Squeezy checklist

Step 3 of the solo launch plan. Free + Pro only. Pro is $99/month or $990/year, per deployment, self-serve. Lemon Squeezy is the merchant of record. Owner: Cat Tan Operations.

Standing alone: every link below opens in a browser. Work top to bottom. Nothing here needs a terminal except steps 4 and 5, and those are copy-paste.

Before you start

  • Lemon Squeezy account created: app.lemonsqueezy.com (docs: docs.lemonsqueezy.com).
  • Business, tax and payout details to hand (Lemon Squeezy pays out and handles sales tax).
  • The signing key PEM is in your password manager/offline media — not on a shared machine. See key operations.
  • You can edit landing/index.html (one line, step 6).

The checklist

  1. Create the store. In the dashboard, create a store for TanCat. Pick the store name, country (United Kingdom), currency (GBP or USD — pick the one you will price in) and a store subdomain such as tancat. The subdomain is what your checkout links sit on.
    Where: dashboard → store switcher → New store.
  2. Activate the store. Lemon Squeezy will not let you sell until the store is activated. Complete the activation flow: confirm your email, add your identity/business details, tax details and payout account. Approval is usually quick but can take a day — do this before you want to go live.
    Where: dashboard → Activate store. The banner at the top tells you what is still missing.
  3. Create the Pro product. Add a product named TanCat Pro Deployment. Product type: subscription. Add two variants:
    VariantPriceBilling
    Pro — monthly$99Every month
    Pro — yearly$990Every year
    Put the same feature list on both (unlimited runs and evidence exports, POM mode, multi-site suites, CI/CD Action, support and updates while licensed, one deployment — whole team, no per-seat charge).
    Where: dashboard → Products → New product.
  4. Turn on licence keys for the product. In the product's settings, enable licence keys and set a prefix (for example TANCAT) and activation limit. Also set the wording the buyer sees on the order-confirmation/thank-you email so they know a key is coming.
    Important — our key is a signed token, not an LS key. The product verifies an offline ed25519 signed token issued by your signing key (see key ops). Lemon Squeezy's own licence keys are a different format. Keep fulfilment offline: sign the buyer's token in step 5 and deliver it. Confirm in the dashboard which fulfilment option your store offers (downloadable fulfilment file vs. licence-key field) before you process a real order.
  5. Generate a batch of signed keys (offline). On the machine that holds the signing key, for each order/buyer generate a token with the real signing tool. One buyer, one deployment id: 
    python scripts/license_gen.py sign \
  --private-key ~/.tancat/license-signing/license_signing_private_key.pem \
  --deployment-id "ACME-PROD" --tier pro --days 365 \
  --out issued/ACME-PROD.key
    For a batch, keep a buyers.csv with deployment_id,email and loop: 
    mkdir -p issued
while IFS=, read -r deployment_id email; do
  python scripts/license_gen.py sign \
    --private-key ~/.tancat/license-signing/license_signing_private_key.pem \
    --deployment-id "$deployment_id" --tier pro --days 365 \
    --out "issued/$deployment_id.key"
done < buyers.csv
    Tool: scripts/license_gen.py. Keep a ledger: order id → deployment id → expiry date.
  6. Upload / deliver the batch. Put the signed tokens where the buyer can get theirs after payment. Use whichever of these your store supports, in order of preference:
    • attach the signed token as the order's fulfilment/download file; or
    • send it from hello@tancat.dev when the order email arrives (manual, safe, no server).
    Do not build a signing-key server or a webhook that holds the private key. The key-ops doc calls that the highest-value secret in the business. Fulfilment stays offline/batch.
  7. Paste the checkout URL into the landing page. Copy the checkout URL for the Pro product from the dashboard (the product's Share → Checkout link, or the Buy link). Open landing/index.html and set it in the one clearly-marked config block near the top: 
    window.TANCAT_CONFIG = {
  checkoutUrl: "https://tancat.lemonsqueezy.com/buy/<your-id>"
};
    Save, deploy the site, and click the pricing card's Buy Pro button. It must open your Lemon Squeezy checkout in a new tab. While checkoutUrl is empty the button safely falls back to the contact section.
  8. Test mode — buy it end to end. Turn on Test mode in the dashboard (top of the page) and place a test purchase with the card 4242 4242 4242 4242, any future expiry, any CVC. Confirm all four:
    • the test order is created and the confirmation email sends;
    • you can produce the buyer's signed token and deliver it;
    • the buyer's install shows License valid — pro tier (deployment ...) (follow install & activate);
    • cancel/refund the test order cleanly.
    A test-mode purchase does not move real money. Delete the test order when done.
  9. Go live. Turn Test mode off. Then walk the page as a stranger:
    • tancat.dev/#pricing shows $99/month and $990/year, and Buy Pro opens the live checkout.
    • Buy Pro with a real card; confirm the charge, the confirmation email, and that you can issue the key.
    • The install page name-checks all three activation routes: AITEST_LICENSE_KEY, AITEST_LICENSE_FILE, and ~/.ai-test-gen/license.key.
    • Terms and privacy name Lemon Squeezy as merchant of record.
    • Refund the real test purchase.
  10. After launch.
    • Keep the signing key backed up (two media, two locations) and test recovery as the key-ops doc says.
    • Keep the ledger and diarise renewals; issue a fresh token before each expiry.
    • Verify the loop any time with pytest tests/test_license_loop_e2e.py.

Definition of done

A stranger can click Buy Pro on the landing page, pay by card, receive a signed key, follow the install page, and see License valid — pro tier (deployment ...) in the product — with no server holding the signing key at any point.
